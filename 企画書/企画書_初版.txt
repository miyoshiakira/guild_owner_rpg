# プロジェクト企画書：guild_owner_rpg

## 1. プロジェクト概要
ユーザーがギルドのオーナーとなり、モンスターを仲間にしながら冒険を進めるブラウザベースの2D-RPG。
**「懐かしの2D体験」**と**「洗練されたモダンな操作感」**の両立を目指す。

## 2. 技術スタック
| レイヤー | 選定技術 | 採用理由 |
| :--- | :--- | :--- |
| **Frontend** | **React 19+** | コンポーネントベースの開発、高速なUI更新。 |
| **UI Library** | **MUI (Material UI)** | グリッドシステム、洗練されたダイアログ、カードUIの活用。 |
| **Local DB** | **IndexedDB (Dexie.js)** | ブラウザ内での高速なオートセーブ、オフライン対応。 |
| **Backend** | **Python (FastAPI/Flask)** | データ検証、Firebase admin SDKとの連携。 |
| **Database** | **Firebase Firestore** | ユーザー間のデータ同期、バックアップ、スケーラビリティ。 |

---

## 3. 画面設計・UIコンポーネント案 (MUIの活用)
現代的なUXを提供するため、ゲーム画面を中央に配置し、周囲をMUIのパネルで囲う「ダッシュボード型」を採用します。

### A. メインゲーム画面 (Game Canvas)
* **フィールドモード:** 2Dタイルマップ。十字キーまたはクリックで移動。
* **バトルモード:** ターン制コマンドバトル。MUIの `Button` グループでコマンドを選択。
* **広告エリア:** サイドバーまたは下部フッターに、ゲーム体験を邪魔しない形で配置。

### B. ギルド管理画面 (MUI Components)
* **モンスター名簿:** `MUI DataGrid` や `Card` を使い、ステータスを可視化。
* **装備変更:** `Drawer`（引き出しUI）を使用して、フィールド画面を離れずに装備を切り替え。
* **進捗同期:** `Appbar` に「クラウド同期状態」を表示。

---

## 4. コアシステム設計

### ① データ永続化フロー
1.  **リアルタイム:** 戦闘終了やアイテム取得のたびに `IndexedDB` へ保存（遅延ゼロ）。
2.  **バックグラウンド:** ユーザーが「保存」ボタンを押す、あるいは一定時間ごとに Python API を経由して `Firestore` へ同期。

### ② モンスター捕獲ロジック
* 戦闘終了時、特定の確率（捕獲率）に基づいて判定。
* 仲間になったモンスターには `UUID` を発行し、個別の個体値（性格、初期ステータス）を IndexedDB に保存。

---

## 5. 画面遷移フロー


1.  **ログイン:** Firebase Auth (Google等) で認証。
2.  **拠点（ギルドハウス）:** 仲間の編成、回復、ショップ。
3.  **フィールド冒険:** 2Dスクロールマップ。敵シンボルまたはランダムエンカウント。
4.  **バトル（シームレス遷移）:** MUIの `Fade` または `Grow` トランジションを使用して、没入感を維持したまま画面切り替え。

---

## 6. モダン化へのこだわり（UX方針）
* **レスポンシブデザイン:** PCではサイドバーを表示し、スマホではボトムナビゲーションに切り替え。
* **ダークモード対応:** MUIのテーマ機能を利用し、夜間のプレイでも目が疲れにくい配色を採用。
* **トースト通知:** モンスター獲得やレベルアップ時、`MUI Snackbar` で心地よいフィードバックを返す。
